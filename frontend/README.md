# RADAR 2.0 프론트엔드 (가안)

성남시 보도 정기 점검의 우선순위를 제안하는 도구의 화면입니다.
기준은 기능정의서 v0.5.1입니다. 이 폴더의 화면은 기능정의서에 적힌 것만 만듭니다.

- 지금은 **사용자 화면**(로그인, 도로관리팀·시 도로과 화면)을 만들었습니다.
- **어드민**(RADAR 운영자 화면)은 다음 단계입니다. `src/admin/`은 비어 있습니다.
- **백엔드는 아직 없습니다.** 화면은 `src/mocks/`의 가짜 데이터로 돕니다.

## 실행 방법 (Windows)

1. Node.js 22 LTS를 설치합니다. (`.nvmrc` 참고)
2. 이 폴더에서 PowerShell을 열고 아래를 실행합니다.

```powershell
npm install
npm run dev
```

3. 브라우저에서 http://localhost:5173 을 엽니다.

| 명령 | 하는 일 |
|---|---|
| `npm run dev` | 개발 서버를 띄웁니다 |
| `npm run build` | 배포용 파일을 만듭니다 (`dist/`) |
| `npm run lint` | 코드 검사를 합니다 |

화면은 폭 1280px 이상에서 씁니다. 크롬이나 엣지를 권장합니다.

## 로그인용 가짜 계정

비밀번호는 모두 `radar1234`입니다. 개발 서버에서는 로그인 화면 왼쪽 아래에도 나옵니다.

| 아이디 | 역할 | 첫 화면 |
|---|---|---|
| `suj` | 수정구 도로관리팀 | 점검 후보 (수정구) |
| `jungwon` | 중원구 도로관리팀 (이미 확정한 구) | 점검 후보 (중원구) |
| `bundang`, `bundang-sidewalk` | 분당구 도로관리팀, 보도관리팀 | 점검 후보 (분당구) |
| `city` | 시 도로과 | 점검 후보 (3개 구) |
| `operator` | RADAR 운영자 | 어드민 준비 중 |

회차는 화면 위쪽 선택 칸에서 바꿉니다. `2027 연간`(검토 중), `2026 하반기 참고`(참고), `2026 연간`(확정) 세 가지를 볼 수 있습니다.

## 폴더 구조와 담당 나누기

```
src/
├─ app/            앱 뼈대 (주소, 로그인·회차 상태)
├─ shared/         사용자·어드민이 같이 쓰는 것 (권한표, 공통 문구, 날짜 서식)
├─ styles/         디자인 시스템 토큰 (사용자·어드민 각각)
├─ user/           사용자 화면
│  ├─ layout/      공통 상단, 상태 띠, 순위 안내 띠
│  ├─ components/  버튼, 표, 모달 같은 공통 부품
│  └─ features/    화면 묶음 (한 묶음을 한 사람이 맡는다)
│     ├─ login/        CM-01
│     ├─ candidates/   US-01~04 점검 후보, 후보 상세, 구 확정
│     ├─ reports/      US-05~09 보고서
│     └─ reference/    US-10~14 기준정보
├─ admin/          어드민 (다음 단계)
├─ api/            화면이 데이터를 받는 유일한 길
└─ mocks/          가짜 서버와 가짜 데이터
```

- 화면 묶음 안은 `pages/`(화면), `components/`(그 묶음 안에서만 쓰는 부품), `copy.js`(화면 문구)로 같습니다.
- 화면 문구는 `copy.js`에만 씁니다. 기능정의서 문구가 바뀌면 이 파일만 고칩니다.
- 역할별로 무엇이 보이는지는 `src/shared/auth/permissions.js` 한 곳에서 봅니다.
- 색은 토큰으로만 씁니다. 코드에 색 코드를 직접 쓰지 않습니다. 토큰은 `src/styles/user-tokens.css`(사용자), `admin-tokens.css`(어드민)입니다. 값을 바꿀 때는 `04_디자인 시스템` 폴더의 원본을 고친 뒤 복사합니다.

## 백엔드를 붙일 때

화면은 `src/api/*.js`의 함수만 부릅니다. 지금 이 함수들은 `src/mocks/server.js`(가짜 서버)를 부릅니다.
백엔드가 생기면 `src/api/` 함수 안쪽만 `fetch`로 바꿉니다. 화면 코드는 바꾸지 않습니다.
`src/mocks/server.js`에는 서버가 해야 할 일(역할별로 걸러 내리기, 사유 검사, 구 확정)이 모여 있습니다. 백엔드가 같은 일을 하면 됩니다.

## 개발용 도구

브라우저 개발자 도구 콘솔에서 씁니다. 화면 기능이 아닙니다.

```js
localStorage.setItem('radar.mock.latency', '2500')  // 응답을 느리게 (1초가 넘으면 회색 뼈대가 보인다)
localStorage.setItem('radar.mock.fail', 'candidates') // 이름이 같은 요청을 실패시킨다 (all = 전부)
localStorage.removeItem('radar.mock.fail')
localStorage.removeItem('radar.mock.state.v1')       // 가짜 서버의 저장 상태(결정, 구 확정)를 처음으로
```

## 데이터를 다룰 때 지킬 것

- 수치지형도 가공 테이블(DB 06~09번)은 국외 반출이 금지돼 있습니다. GitHub는 해외 서버이므로 이 저장소에 넣지 않습니다.
- 민원 테이블(79번)도 넣지 않습니다.
- 지금 들어 있는 격자 위치(`src/mocks/data/seongnam_cells.json`)는 DB 01번 격자 테이블의 공개 격자(번호, 중심 좌표, 구, 동)입니다. 점수, 근거, 결정, 민원은 모두 가짜입니다.
- 저장소는 비공개(private)로 만듭니다.

## Windows에서 같이 쓸 때

- 파일·폴더 이름은 영어로만 씁니다. 한글 이름은 맥에서 만든 것이 Windows에서 깨질 수 있습니다. 한글은 화면 문구에만 씁니다.
- import 경로의 대소문자는 파일 이름과 똑같이 씁니다.
- 줄바꿈은 `.gitattributes`가 LF로 맞춥니다. CSV 파일만 CRLF입니다.
