# AI-07 팀 연결 안내

## 담당 기능
AI-07은 계산 완료된 점수·순위와 전달된 근거를 설명하는 기능입니다.
점수 계산/후보 선정/민원 분류/조치 제안 기능은 다른 담당 기능이며 여기서 재계산하지 않습니다.
실제 RADAR 자료를 외부 LLM으로 전송하지 않습니다. DB는 읽기 전용입니다.

## 이번 develop ZIP과의 관계
사용자가 2026-10-21 제공한 AXI_RADAR_2.0_2026-develop(1).zip을 확인했습니다.
이 사본에는 프론트엔드만 있고 공통 Python 서버는 없습니다. 새 폴더 backend/ai07에 기존 AI-07 Python 구현을 모았습니다.
기존 프론트엔드, 루트 README/CONTRIBUTING, PR 양식은 수정하지 않습니다.
이것은 제공된 ZIP과의 비교이며 현재 GitHub develop의 추가 변경까지 확인한 것은 아닙니다.

## 호출 담당자가 알아야 할 내용
- 실행 목록: GET /api/ai07/db/runs
- 후보 목록: GET /api/ai07/db/candidates?run_id=...
- 설명 조회: GET /api/ai07/db/explanation?run_id=...&gid=...
- 후보 식별은 실행 번호(run_id)와 격자 ID(gid)를 함께 사용합니다.
- 응답의 explanation을 사용하되 실행/격자/점수/순위가 선택 후보와 일치하는지 확인합니다.
- 점수는 소수 문자열, 실행 번호도 문자열입니다. NULL을 0으로 바꾸지 않습니다.
- no_results / not_found / missing_values이면 이전 후보나 가상 결과를 대신 표시하지 않습니다.
- 503 등 조회 실패 시 오류 상태를 표시하고 실제 결과를 임의 생성하지 않습니다.
- API 상세, 제한, 응답 필드는 docs/api/ai07-db-readonly.md를 따릅니다.

## 현재 설명의 한계
DB 조회는 priority_run, priority_candidate 두 테이블만 사용합니다.
저장 점수·순위·규칙 버전을 요약하며 항목별 기여, 민원 반영 여부, 지표 출처/기준일, 승인 상태는 이 조회로 받지 못합니다.
따라서 왜 그 순위인지 전체 근거를 설명하는 연결은 아직 완료되지 않았습니다.
실행 당시 근거를 점수 담당자와 맞춘 뒤 추가해야 하며 최신 grid_feature를 무조건 붙이지 않습니다.

## 팀과 맞출 일
1. 계산 결과가 저장되는 시점과 실행 ID/격자 ID의 의미
2. 실행 당시 근거와 기여점수를 받는 방식
3. 설명문 저장 여부·위치 및 공통 응답 형식
4. 공통 서버에 API를 붙이는 담당자, 경로 및 실행 방식
5. 사용자 인증과 구별 접근 권한

현재 서버에는 사용자 인증·관할별 접근 제어가 없고 loopback 개발용으로 제한되어 있습니다.
공개 배포를 위해 주소 제한만 해제하지 않습니다. 공통 서버의 인증·권한을 연결해야 합니다.
이 제출에 프론트엔드 연결 코드는 포함하지 않았습니다. 화면 담당자는 명세에 따라 별도 브랜치에서 연결합니다.

## 확인된 이력과 이번 재검사 구분
사용자 PC에서는 이전 데모의 React→Python→공용 DB 빈 실행 목록 조회를 확인했습니다.
당시 DB에 계산 실행 기록이 없어 실제 계산 결과 설명의 통합 확인은 남아 있습니다.
이번 제출 준비에서는 Python 자동 검사를 가상 DB로 다시 실행했습니다. 실제 공용 DB 접속·변경은 하지 않았습니다.

## 올릴 때
브랜치 feature/ai-07에 backend와 docs 두 폴더만 올립니다. ZIP 파일 자체를 저장소에 올리지 않습니다.
폴더가 이미 있으면 전체 폴더를 교체하지 말고 AI-07 파일 경로를 비교합니다.
프론트 파일·실제 데이터·API 키·비밀번호·가상환경·실행 로그는 포함하지 않습니다.
PR은 develop을 대상으로 만들되 변경 파일을 진이가 확인하고 팀원 1명 이상 검토한 뒤 최종 OK 후 병합합니다.
