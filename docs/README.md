# RADAR 2.0 — AI-10

## 1. 기능 개요

AI-10은 보행환경 관련 판정값과 근거자료를 입력받아 **문제 유형별 조치 제안 문장 틀의 초안**을 생성하는 기능입니다.

생성된 초안은 운영자가 근거와 표현을 검토·수정한 뒤 승인하며, 승인된 문장을 대상별 정보에 맞게 활용하는 구조를 목표로 합니다.

AI-10은 위험도 판정, 현장 사실 확정, 법령의 최종 해석 및 운영자 승인 결정을 자동으로 수행하지 않습니다.

**CK-01~14는 과거 개발·검증에 사용한 참고 예시이며, AI-10의 범용 판정 기준이나 필수 생성 조건이 아닙니다.**

| 경로 | 역할 |

## 4. AI-10 입력과 근거자료

AI-10은 문제 설명, 판정 결과, 시설 식별자, 근거 상태 등의 정보를 이용해 초안 생성을 수행합니다.

판정 근거 입력 연결을 지원하는 테이블은 다음과 같습니다.

| 판정 테이블 | 내용 |
|---|---|
| `assess_crosswalk` | 횡단보도 관련 판정 |
| `assess_sidewalk` | 보도 관련 판정 |
| `assess_intersection` | 교차로 관련 판정 |
| `assess_zone` | 보호구역 관련 판정 |

판정 테이블을 조회하거나 입력으로 구성하는 기능은 존재하지만, 실제 운영 생성 호출까지 연결된 경로는 확인되지 않았습니다.

민원 관련 텍스트와 격자 식별자를 입력받을 수 있으나, 별도 민원·격자 테이블을 직접 조회해 AI-10 근거로 전달하는 경로도 현재 확인되지 않았습니다.

SRC 출처 식별자는 DB 56 자료 목록을 기준으로 검토합니다. 다만 개별 판정값과 SRC 번호 사이의 연결 근거는 아직 확인되지 않았으므로, 출처를 추정해 자동 지정하지 않습니다.

## 5. 조치 제안 초안 생성 흐름

AI-10의 목표 업무 흐름은 다음과 같습니다.

1. 문제 설명 및 판정 근거 입력
2. 필수 입력과 근거 상태 확인
3. 공통 LLM을 통한 문장 초안 생성
4. 자동 검토 신호 및 검토 메모 확인
5. 운영자 검토·수정·승인
6. 승인된 문장 틀을 대상 정보에 맞게 표시

**이 흐름은 목표 구조이며, 모든 단계가 운영 환경에서 연결·검증되었다는 뜻은 아닙니다.**

운영자 승인 전 문장을 최종 조치 결과나 확정된 행정 판단으로 취급하지 않습니다.

## 6. 외부 전송 안전성

현재 실제 생성 호출은 다음 조건을 사용합니다.

```python
result = call_llm(
    "ai10_draft",
    [{"role": "user", "content": prompt}],
    data_ids=[],
    contains_raw=True,
    response_format="json",
    schema=CaseDraftOutput,
)
```

`contains_raw=True`는 원본값, 민원 주장, 위치정보 등이 입력에 포함될 가능성을 고려한 설정입니다.

외부 전송 허용 SRC 목록이 확정되지 않았으므로 내부 모델을 사용하며, 외부용 요청 구성 기능은 실제 생성 호출에 연결하지 않았습니다.

외부 전송용으로 사용할 때에는 원본 좌표·도형·개인정보·출처 미확인 자료가 포함되지 않았는지 별도 확인해야 합니다.

특히 수치지형도 관련 원본 위치정보와 공개되지 않은 보행신호 자료는 외부 전송 허용 대상으로 임의 지정하지 않습니다.

## 8. 팀 통합 시 주의사항

- CK 예시는 AI-10 범용 판정 기준으로 사용하지 않습니다.
- 판정값, 근거자료, 처리 상태, 증빙 및 현장 확인 여부는 실제 데이터와 최신 명세를 기준으로 다룹니다.
- 개별 판정값과 SRC 번호의 관계를 추정해 확정하지 않습니다.
- 운영자 검토·승인 이전의 생성 문장은 최종 확정 문장으로 취급하지 않습니다.
- 개발용 API 및 개발용 검토 저장소를 운영 인증·인가 또는 운영 DB와 동일하게 취급하지 않습니다.
- 실제 생성 경로의 외부 모델 호출은 허용 출처와 입력 안전성이 확인되기 전까지 활성화하지 않습니다.
