# 민원 적재 (W07-01)

성남데이터넷 '민원 상세정보 현황' **한 달치 파일**을 79 `src_complaint` · 80 `src_complaint_change` · 84 `data_upload`에 넣는다. 담당: 규칙은 `적재 규칙 명세서 v1.1`, 기능은 C-01·C-02·C-09·C-10.
상세 기록·결정·정의서 수정안은 `작업파일/261022/w07-load/`에 있다.

## 쓰는 법
```text
POST /api/c09/uploads?source=…&refDate=2026-09-30&periodStart=2026-09-01&periodEnd=2026-09-30[&dataName=…][&isOfficialRaw=가공본][&fileName=…]
본문: xlsx 파일 그대로 (multipart 아님)
GET  /api/c09/uploads?limit=50      올린 기록 (84 data_upload 최신 순)
```
- 출처·기준일·기간은 필수. 기간은 한 달(1일~말일). 파일 안 민원등록일이 기간 밖이면 거절.
- 한 번에 파일 하나. 파일마다 84에 한 줄. 같은 달을 다시 올리면 바뀐 칸만 고치고 80에 남긴다.
- **RADAR 운영자(`operator`)만** 쓴다 (`Authorization: Bearer <토큰>`). 로그인한 계정이 84 `uploaded_by`에 자동 기록된다.
- 적재는 실행 기록(`track("업로드")`)에 남고, 실패하면 운영자 알림이 쌓인다. 85·86 표가 없는 DB에서는 기록만 못 남기고 적재는 정상이다.
- DB 접속은 `.env`의 `RADAR_DB_*`.

```powershell
# 로컬 DB로 시험 적재 (로컬이 아니면 --allow-shared-db 없이는 멈춘다)
uv run python scripts/load_month.py <xlsx> --month 2026-09 --source "<출처>" --ref-date 2026-09-30
uv run python scripts/load_recurrence.py        # 재발 표시를 DB 값만으로 다시 계산
uv run python scripts/load_verify.py <79_src_complaint.txt> <xlsx> 2026 9   # 79와 민원ID 건수 비교
uv run python -m pytest tests -k load
```

## 흐름
1 올리기(출처·기간) → 형식·기간 확인 → 2 민원ID → 3 칸 쌓기·규칙 가림·본문 좌표→격자 → 4 AI-01(메모리, 새 민원과 결과 없는 민원만) → 원문 버림 → 재발 표시 → 검사 8가지 → 신규/기존/갱신 + 80 → 84 결과.
원문(제목·본문)은 메모리에서만 쓰고 DB·파일·로그에 남기지 않는다. 올린 파일도 저장하지 않는다.

## AI-01 · AI-03
- `app/services/ai01/refine.py`(AI-01 담당)가 있으면 그 함수를 부르고, 없거나 불러오지 못하면 `app/services/load/ai01_stub.py`(가짜)로 대체한다. 가짜 결과는 DB에 쓰지 않으며, 대체되면 응답 `warnings`에 알린다.
- 새 민원과 아직 AI-01 결과가 없는 기존 민원에만 부른다. 이미 결과가 있는 민원은 다시 부르지 않는다 (모델을 바꿨을 때만 `rerun_ai01`).
- 진짜 함수에는 `upload_id`·`request_id`를 넘겨 AI-01의 실행 기록('분류')이 업로드와 이어진다.
- 가림 실패·오류 민원은 AI-01 칸을 비워 두고 적재는 계속한다. 가린 요약에 개인정보 꼴이 남은 민원은 그 민원만 `가림 실패`로 두고, 파일 전체를 되돌리지 않는다.
- 진짜 함수를 쓰려면 AI-01 문서(`docs/ai01/README.md`)의 준비(선택 묶음 `ai01`, Ollama 모델, `AI01_COMMON_WORDS`)가 필요하다. 적재가 쓰는 `openpyxl`은 선택 묶음이 아니라 **기본 dependencies**에 있어야 한다.
- **처리 시간 (2025-11 월 파일 표본, 이 PC의 Ollama `exaone3.5:7.8b`, 이름 모델 CPU)**: 가림은 건당 0.04~0.08초이고, 느린 것은 내부 모델 호출이다 (요약 약 2.5초, 분류 약 2.2초; 일반 민원은 4.2초·2.9초). 안전신문고는 가린 글이 모두 200자를 넘고 98%가 분류 모델을 거쳐 건당 약 5~6초, 월 8,860건이면 약 12시간이다. 전처리 뒤에도 안전신문고 안내 문구 27줄(약 1,300자)이 남아 있기 때문으로 보이며, 이 줄을 빼면 가린 글 길이 중앙값이 1,605자에서 261자로 줄어든다. 적재는 요청 안에서 끝까지 처리하므로 진짜 AI-01로 실제 월 파일을 올리려면 AI-01 쪽 처리량부터 줄여야 한다.
- 주소 변환(좌표 채우기)은 AI-03 몫이다. 적재는 본문에 이미 있는 위도·경도만 격자로 바꾼다.

## C-08 연계 (분류 결과 표본 확인)
C-08이 쓰는 값을 적재가 대신 지키거나 기록한다. 모두 DB에 칸·표가 있을 때만 동작하고, 없으면 해당 기록만 건너뛰며 응답 `warnings`에 알린다.
- **79 `class_method`** (관련 여부를 정한 방법: 규칙 / AI / 사람): AI-01이 돌려준 방법을 저장한다. 가림 실패·오류·가짜 함수는 비워 두고, 신뢰도나 근거 문구로 추측하지 않는다.
- **사람이 고친 값 보호**: `class_method`가 `사람`인 민원은 AI-01에 보내지 않고 관련 여부·방법·신뢰도·근거를 덮어쓰지 않는다 (`rerun_ai01`도 마찬가지). 유형만 고친 경우의 보호는 유형 목록(ISS-016) 이후.
- **95 `complaint_upload_membership`**: 성공한 업로드의 신규·기존 민원 모두에 대해 거래가 끝난 시점의 분류 상태(접수일, 구, 가린 요약, 관련 여부, 유형, 방법, 신뢰도, 근거)를 같은 거래 안에서 기록한다. 업로드가 실패하면 함께 되돌려진다. 신뢰도는 95의 DECIMAL(6,5)로 반올림된다.
